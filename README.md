## Overview

TaskWeave Content Orchestrator manages the full lifecycle of LinkedIn content for engineering leaders. It connects a human editorial workflow with AI-powered draft generation via two paths:

1. **TeamWeave** — Posts a task to a shared AI orchestration API that runs a Step Functions writer agent, then fetches the resulting artifact from S3.
2. **Gemini (BAU fallback)** — Calls Google Gemini directly when TeamWeave is unavailable.

Once approved, articles are published to S3 and automatically included in the weekly newsletter sent to all subscribers via AWS SES.

---

## Features

| Feature | Details |
|---------|---------|
| **AI Draft Generation** | 3 LinkedIn draft variants per article (TeamWeave primary, Gemini fallback) |
| **Editorial Workflow** | 7-state article lifecycle with admin API actions |
| **S3 Publishing** | Approved articles uploaded to `docs/articles/{id}.json` |
| **Weekly Newsletter** | Auto-generated by Gemini, sent to SES subscribers every Monday |
| **Approval Notifications** | SNS → email alert when a draft is ready for review |
| **Subscriber Management** | Subscribe/unsubscribe via API, backed by DynamoDB + SES contact list |
| **Audit Trail** | Every state change logged as an immutable DynamoDB event |
| **Fully Serverless** | Lambda, DynamoDB, S3, SES, SNS, EventBridge — zero servers |
| **CI/CD** | GitHub Actions with OIDC (no long-lived AWS keys) |

## Architecture

The system is built on AWS Lambda and deployed via AWS SAM. Two CloudFormation stacks cooperate:

- **`tarun-content-team`** (shared) — Artifact S3 bucket, Step Functions state machine, TeamWeave HTTP API
- **`tarun-admin-content`** (this repo) — Content orchestration: APIs, automation, newsletter, DynamoDB, SNS

```
Admin ──▶ API Gateway ──▶ AdminApi Lambda ──▶ DynamoDB
                     ├──▶ PublicApi Lambda             │ (on approve)
                     ├──▶ AppointmentApi Lambda        ▼
                     └──▶ SiteData Lambda          S3 Bucket

EventBridge (Mon 15:15 UTC)
  └──▶ GenerateDrafts Lambda ──▶ TeamWeave API ──▶ Step Functions
                               └──▶ Gemini API (fallback)
                               └──▶ SNS (approval notification)

EventBridge (Mon 00:00 UTC)
  └──▶ Newsletter Lambda ──▶ Gemini API ──▶ SES (send to subscribers)
```

For full diagrams see the [Documentation](#documentation) section.

## Article Lifecycle

```
DRAFT ──(generate)──▶ AWAITING_APPROVAL ──(approve)──▶ APPROVED ──(mark-published)──▶ PUBLISHED
  ▲                          │                                                               │
  │               (request-edits)                                                 (archive)  │
  │                          ▼                                                    ARCHIVED ◀─┘
  └──────── REVISION_REQUESTED ──(submit)──▶ AWAITING_APPROVAL

                         (reject / mark-failed) ──▶ FAILED
```

| Status | Available Actions |
|--------|------------------|
| `DRAFT` | `generate`, `submit-for-approval`, `request-edits`, `reject` |
| `REVISION_REQUESTED` | `submit-for-approval`, `reject` |
| `AWAITING_APPROVAL` | `approve`, `request-edits`, `reject` |
| `APPROVED` | `mark-published`, `archive` |
| `PUBLISHED` | `archive` |
| `FAILED` | `submit-for-approval`, `archive` |
| `ARCHIVED` | *(none)* |

## Quick Start

### 1. Clone and install

```bash
git clone https://github.com/rajatarun/ai-content-orchestrator.git
cd ai-content-orchestrator
pip install -r requirements.txt
```

### 2. Store the Gemini API key

```bash
aws secretsmanager create-secret \
  --name gemini/api_key \
  --secret-string '{"key":"YOUR_GEMINI_API_KEY"}'
```

### 3. Deploy

```bash
bash scripts/deploy.sh
```

Or manually with SAM:

```bash
sam build
sam deploy --guided \
  --region us-east-1 \
  --stack-name tarun-admin-content \
  --parameter-overrides \
    ArtifactBucket=<bucket-from-shared-stack> \
    StatusFunctionArn=<arn-from-shared-stack> \
    HttpApiUrl=<url-from-shared-stack>
```

### 4. Verify deployment

```bash
curl https://<api-id>.execute-api.us-east-1.amazonaws.com/prod/admin
# → {"ok": true}
```

## API Reference

Base URL: `https://{restApiId}.execute-api.us-east-1.amazonaws.com/prod`

All endpoints return `application/json`. CORS is enabled for all origins (`*`).

### Articles

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/admin` | Health check |
| `POST` | `/admin/articles` | Create a new article (`title` required) |
| `GET` | `/admin/articles?status=DRAFT&limit=20` | List articles by status |
| `GET` | `/admin/articles/{id}` | Get article with available CTAs |
| `PATCH` | `/admin/articles/{id}` | Update article fields |
| `GET` | `/admin/articles/{id}/events` | Get audit event history |

### Article Actions

| Method | Path | Body | Description |
|--------|------|------|-------------|
| `POST` | `/admin/articles/{id}/actions/generate` | — | Trigger async AI draft generation |
| `POST` | `/admin/articles/{id}/actions/approve` | — | Approve draft + publish to S3 |
| `POST` | `/admin/articles/{id}/actions/submit-for-approval` | — | Submit for review |
| `POST` | `/admin/articles/{id}/actions/request-edits` | `{ "revisionNote": "..." }` | Request revision |
| `POST` | `/admin/articles/{id}/actions/reject` | `{ "reason": "..." }` | Reject → FAILED |
| `POST` | `/admin/articles/{id}/actions/mark-failed` | `{ "reason": "..." }` | Mark as failed |
| `POST` | `/admin/articles/{id}/actions/archive` | `{ "reason": "..." }` | Archive |
| `POST` | `/admin/articles/{id}/actions/mark-published` | `{ "publishedAt": "...", "publishedUrl": "..." }` | Mark as published |

### Newsletter

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/admin/newsletter/actions/generate` | Generate newsletter preview via Gemini |
| `POST` | `/admin/newsletter/actions/send` | Send newsletter to all active subscribers |

### Subscribers

| Method | Path | Body | Description |
|--------|------|------|-------------|
| `GET` | `/admin/subscribers` | — | List all active subscribers |
| `POST` | `/admin/subscribers` | `{ "email": "..." }` | Add subscriber |
| `DELETE` | `/admin/subscribers/{email}` | — | Remove subscriber |

### Public Endpoints

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/public/subscribe` | Subscribe to newsletter |
| `POST` | `/public/appointment` | Request an appointment |
| `GET` | `/site/posts` | List published articles (from S3) |
| `GET` | `/site/posts/{id}` | Get a single published article |

## CI/CD

Automated deployment via [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml):

```
Push to main
  │
  ├─ Configure AWS credentials (OIDC — no long-lived secrets)
  │   Role: arn:aws:iam::239571291755:role/teamweave-github-actions-sam-deployer
  ├─ Setup Python 3.11 + SAM CLI
  ├─ sam build + sam validate (lint)
  ├─ Load shared stack outputs from tarun-content-team
  │   (ArtifactBucket · StatusFunctionArn · HttpApiUrl)
  └─ sam deploy → tarun-admin-content
```

**Required GitHub Variables:**

| Variable | Default | Description |
|----------|---------|-------------|
| `REGION` | `us-east-1` | AWS deployment region |
| `STACK_NAME` | `tarun-admin-content` | CloudFormation stack name |
| `TEAM_STACK_NAME` | `tarun-content-team` | Shared stack name for cross-stack outputs |

### Rendering PlantUML Diagrams

Both diagrams use **locally bundled** libraries — no internet access required during rendering.
They must be rendered from the `docs/` directory so relative `!include` paths resolve correctly.

**VS Code:** Install the PlantUML extension, open a `.puml` file, press `Alt+D`.

**CLI:**

```bash
cd docs
plantuml c4-architecture.puml       # renders all 4 @startuml blocks → PNG files
plantuml aws-infrastructure.puml    # → aws-infrastructure.png
```

**Docker (no local PlantUML install needed):**

```bash
cd docs
docker run --rm -v "$(pwd)":/work plantuml/plantuml:latest c4-architecture.puml
docker run --rm -v "$(pwd)":/work plantuml/plantuml:latest aws-infrastructure.puml
```
